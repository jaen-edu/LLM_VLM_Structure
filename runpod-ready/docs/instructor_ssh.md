# 강사용 가이드: 학교에서 SSH 사용을 허용한 환경에서 VS Code로 RunPod Pod 연결하기

## 1. 목적

이 문서는 다음 수업 환경을 기준으로 작성했습니다.

- 강사 1명, 학생 15명
- 강사가 RunPod Pod 16개를 미리 준비
- 학생들은 각자 Windows 11 PC의 VS Code로 자신에게 배정된 Pod에 접속
- 학교가 SSH 사용을 허용하는 방향으로 방화벽 정책을 조정함

이 문서의 목표는 강사가 수업 전에 무엇을 준비해야 하는지, 학생들에게 어떤 정보를 나눠 줘야 하는지, 수업 당일 어떤 순서로 운영해야 하는지를 단계별로 정리하는 것입니다.

## 2. 가장 먼저 알아야 할 점

> **중요한 전제**
> 학교가 외부 22번 포트를 열어주었다고 해서, RunPod의 VS Code 연결이 무조건 22번으로 이뤄지는 것은 아닙니다.
> RunPod에서 VS Code Remote-SSH는 보통 `Basic SSH`가 아니라 `SSH over exposed TCP`를 사용하며, 이때 학생이 실제로 접속하는 외부 포트는 `17445` 같은 고포트일 수 있습니다.

즉, 이번 가이드는 아래 조건이 성립한다고 보고 작성합니다.

1. 학교가 SSH 계열 접속을 허용한다.
2. 학생 PC에서 RunPod Pod의 실제 외부 SSH 포트까지 도달할 수 있다.
3. 강사가 학생에게 배포하는 것은 `SSH over exposed TCP` 기준의 접속 정보다.

## 3. Basic SSH와 SSH over exposed TCP의 차이

RunPod 문서 기준으로 SSH 방식은 크게 두 가지를 구분해 이해하면 됩니다.

### Basic SSH

- 예시: `ssh <ID>@ssh.runpod.io -i ~/.ssh/id_ed25519`
- 빠른 터미널 접속용
- SCP, SFTP 같은 전체 SSH 기능을 지원하지 않음
- VS Code Remote-SSH용 기본 경로로 보지 않는 것이 안전함

### SSH over exposed TCP

- 예시: `ssh root@213.173.108.12 -p 17445 -i ~/.ssh/id_ed25519`
- 공인 IP와 외부 포트를 사용
- VS Code Remote-SSH에서 사용하는 표준 방식
- 파일 전송, 원격 서버 설치, 일반 SSH 기능에 적합

수업 문서와 학생 안내는 반드시 두 번째 방식 기준으로 준비합니다.

## 4. 권장 운영 구성

강의 운영은 아래 구성을 권장합니다.

- 학생용 Pod 15개
- 강사용 또는 예비용 Pod 1개
- 총 16개 Pod

예비 Pod 1개는 거의 필수입니다. 한 학생의 접속 문제를 오래 잡기보다 예비 Pod로 즉시 교체하는 편이 수업 흐름을 지키기 쉽습니다.

## 5. 준비 일정 권장안

### D-3 ~ D-1: 학생 공개키 수집

학생들에게 아래를 미리 안내합니다.

1. Windows 11 PC에 VS Code 설치
2. `Remote - SSH` 확장 설치
3. SSH 키 생성
4. 공개키 제출

학생에게서 받는 것은 `id_ed25519.pub` 내용 전체 한 줄입니다. 개인키는 절대 받지 않습니다.

### D-1: 템플릿과 테스트 Pod 검증

1. RunPod 공식 템플릿을 우선 검토합니다.
2. `SSH Terminal Access`를 지원하는지 확인합니다.
3. 테스트 Pod 1개를 먼저 띄웁니다.
4. Windows 11 환경에서 VS Code Remote-SSH 접속까지 검증합니다.

### 수업 시작 30~60분 전: 본 수업용 Pod 16개 실행

1. 학생용 15개와 강사용 1개를 기동합니다.
2. 모든 Pod가 `Running` 상태인지 확인합니다.
3. Telemetry가 들어오는지 확인합니다.
4. 각 Pod의 접속 정보를 표로 정리합니다.

## 6. 강사용 준비물 체크리스트

- RunPod 계정과 결제 수단
- 학생 15명의 공개키
- 강사용 공개키
- VS Code가 설치된 Windows 11 테스트 PC 1대
- 학생별 Pod 배정표

권장 배정표 컬럼 예시는 아래와 같습니다.

| Pod 번호 | 배정 대상 | Pod 이름 | 공인 IP | 외부 SSH 포트 | 접속 별칭 | 상태 |
| --- | --- | --- | --- | --- | --- | --- |
| 01 | 학생1 | class-pod-01 | 213.173.xxx.xxx | 17445 | rp-class-01 | 준비 완료 |

## 7. SSH 키 운영 방식 결정

### 방식 A: 강사 계정에 학생 공개키 전체 등록

가장 단순한 운영 방식입니다.

1. 학생 15명 공개키와 강사용 공개키를 RunPod 계정의 `SSH Public Keys`에 등록합니다.
2. 그 뒤 Pod를 시작하면 공개키가 Pod에 주입됩니다.

장점:

- 준비가 빠릅니다.
- 여러 Pod를 한 번에 운영하기 쉽습니다.

주의:

- 모든 Pod에 여러 공개키가 들어갈 수 있습니다.
- 학생별 접속 정보 관리가 느슨하면 다른 Pod에 잘못 접속할 수 있습니다.

### 방식 B: Pod별로 해당 학생 공개키만 주입

보안 분리가 더 잘 됩니다.

1. Pod별 `SSH_PUBLIC_KEY` 환경 변수를 사용하거나
2. Pod 시작 후 웹 터미널에서 `~/.ssh/authorized_keys`를 직접 관리합니다.

장점:

- 학생별 Pod 접근을 더 명확히 분리할 수 있습니다.

주의:

- 16개 Pod를 준비할 때 수작업이 늘어납니다.

수업 준비 시간이 제한적이면 방식 A, 학생별 접근 분리를 더 엄격히 하고 싶으면 방식 B를 선택합니다.

## 8. 템플릿 선택 기준

### 공식 템플릿 사용 시

1. Pod 생성 화면에서 공식 템플릿을 선택합니다.
2. `SSH Terminal Access` 또는 이에 준하는 SSH 지원 여부를 확인합니다.
3. `/workspace`를 사용할 수 있도록 영구 스토리지를 고려합니다.

### 커스텀 템플릿 사용 시

아래 조건이 모두 필요합니다.

1. `openssh-server` 설치
2. `sshd` 실행
3. 내부 TCP 22 노출
4. 공개키가 `~/.ssh/authorized_keys`에 반영됨

커스텀 템플릿은 수업 전날까지 VS Code 접속 검증을 반드시 끝내야 합니다.

## 9. Pod 16개 준비 절차

1. Pod 이름 규칙을 정합니다.

예시:

- `class-pod-01`
- `class-pod-02`
- `class-pod-03`
- `class-pod-16`

2. 수업에 필요한 GPU, 디스크, 템플릿을 선택합니다.
3. 가급적 16개 Pod의 사양을 동일하게 맞춥니다.
4. 학생용 15개와 예비용 1개를 모두 실행합니다.
5. 각 Pod가 완전히 초기화될 때까지 기다립니다.

## 10. 학생에게 배포할 접속 정보 정리

각 Pod에서 아래 순서로 정보를 확인합니다.

1. RunPod 콘솔의 Pods 페이지로 이동
2. 대상 Pod 선택
3. `Connect` 클릭
4. `SSH` 탭 선택
5. `SSH over exposed TCP` 항목의 명령 확인

예시는 아래와 같습니다.

```bash
ssh root@213.173.108.12 -p 17445 -i ~/.ssh/id_ed25519
```

학생에게 전달할 핵심 정보는 아래 네 가지입니다.

- 호스트 IP
- 외부 SSH 포트
- 사용자명 `root`
- 원격 작업 폴더 `/workspace`

실무적으로는 아래 두 형식 중 하나를 권장합니다.

### 전달 형식 A: 필드만 전달

- HostName: `213.173.108.12`
- Port: `17445`
- User: `root`
- Folder: `/workspace`

### 전달 형식 B: SSH config 예시로 전달

```ssh-config
Host rp-class-01
    HostName 213.173.108.12
    User root
    Port 17445
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
```

## 11. 학교 네트워크 사전 검증

이번 시나리오는 학교가 SSH 사용을 허용한 경우이지만, 실제 검증은 여전히 필요합니다.

중요한 것은 **22번 자체가 아니라, 학생이 접속할 실제 외부 포트**입니다.

PowerShell에서 아래처럼 확인합니다.

```powershell
Test-NetConnection 213.173.108.12 -Port 17445
```

`TcpTestSucceeded : True`가 나오면 네트워크 레벨은 통과입니다.

가능하면 VS Code 전에 터미널 SSH도 한 번 확인합니다.

```powershell
ssh root@213.173.108.12 -p 17445
```

만약 이 단계에서 실패하면 아래 중 하나입니다.

1. Pod 초기화가 아직 끝나지 않음
2. 외부 SSH 포트가 바뀌었음
3. 학교가 22번은 열었지만, RunPod가 배정한 외부 고포트는 막고 있음

세 번째라면 방화벽 정책을 다시 확인해야 합니다. 즉, 학교가 목적지 22번만 허용하는 정책이면 RunPod VS Code 연결에는 충분하지 않을 수 있습니다.

## 12. 강사용 리허설 절차

수업 전에는 최소 1회 아래 순서로 실제 검증합니다.

1. Windows 11 PC에서 VS Code 실행
2. `Remote - SSH` 확장 설치 확인
3. 새 SSH Host 등록
4. Pod 연결
5. 플랫폼 선택 시 `Linux` 선택
6. `/workspace` 폴더 열기
7. 터미널에서 명령 실행

예시:

```bash
pwd
ls
nvidia-smi
```

8. 간단한 파일을 생성하고 유지되는지 확인

```bash
echo test > /workspace/connection-check.txt
```

## 13. 수업 당일 운영 순서

1. 학생별 Pod 번호와 접속 정보를 배포합니다.
2. 강사용 Pod로 먼저 접속 시연을 합니다.
3. 학생 접속이 시작되면 Pod를 재시작하지 않습니다.
4. 접속이 안 되는 학생은 오래 붙잡지 말고 예비 Pod 전환 여부를 먼저 판단합니다.
5. 접속 후 모든 학생이 `/workspace`를 열었는지 확인합니다.

## 15. 자주 발생하는 문제와 대응

### 문제 1. RunPod에서 SSH 명령이 하나만 보인다

원인:

- 템플릿이 `SSH over exposed TCP`를 지원하지 않을 수 있습니다.

조치:

1. 공식 템플릿인지 확인합니다.
2. `SSH Terminal Access`가 활성화되었는지 확인합니다.
3. 커스텀 템플릿이면 TCP 22 노출과 `sshd` 실행을 확인합니다.

### 문제 2. `Permission denied (publickey)`가 발생한다

원인:

- 공개키가 Pod에 제대로 반영되지 않음
- 학생 PC가 다른 개인키를 사용함
- Pod 실행 후 공개키를 등록해서 자동 주입이 되지 않음

조치:

1. RunPod에 등록된 공개키 형식이 `ssh-ed25519 ...` 전체인지 확인합니다.
2. Pod 시작 이후 키를 등록했다면 웹 터미널로 `authorized_keys`를 직접 수정하거나 Pod를 다시 배포합니다.
3. 학생 SSH config의 `IdentityFile` 경로를 확인합니다.

### 문제 3. 호스트 키 경고가 발생한다

원인:

- Pod 재배포 또는 재시작으로 호스트 키가 바뀜

조치:

학생에게 아래 명령을 안내합니다.

```powershell
ssh-keygen -R [213.173.108.12]:17445
```

그 후 다시 접속합니다.

### 문제 4. VS Code가 연결 중 멈춘다

원인:

- 네트워크 문제
- Pod 초기화 미완료
- VS Code Server 설치 실패

조치:

1. 먼저 `Test-NetConnection`으로 실제 포트를 검사합니다.
2. RunPod에서 Telemetry가 들어오는지 확인합니다.
3. 이미 한 번 접속했던 Pod라면 아래를 실행 후 재접속합니다.

```bash
rm -rf ~/.vscode-server
```

### 문제 5. Pod를 중지했다가 다시 시작했더니 접속이 안 된다

원인:

- RunPod 외부 포트가 바뀌었을 가능성이 높습니다.

조치:

1. 새 공인 IP와 새 외부 포트를 확인합니다.
2. 학생 SSH 설정을 갱신합니다.
3. 시간이 부족하면 예비 Pod로 전환합니다.

7. 접속 실패 학생은 예비 Pod로 우회
