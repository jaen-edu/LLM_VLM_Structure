# 강사용 가이드: 학교 방화벽에서 22번 포트가 막힌 환경에서 VS Code로 RunPod Pod 연결하기

## 1. 목적

이 문서는 다음 수업 환경을 기준으로 작성했습니다.

- 강사 1명, 학생 15명
- 강사가 RunPod Pod 16개를 미리 준비
- 학생들은 각자 Windows 11 PC의 VS Code로 자신에게 배정된 Pod에 접속
- 학교 네트워크에서 외부 22번 포트 아웃바운드가 차단됨

> **SSH over exposed TCP**
> Pod 내부의 SSH 서비스는 보통 22번 포트를 사용합니다. 하지만 RunPod는 이 내부 22번을 외부의 다른 고포트(예: 17445)로 매핑해 줄 수 있습니다. 학교 방화벽이 22번만 막는 경우, 학생 PC는 이 외부 고포트로 접속하면 됩니다.

## 2. 핵심 운영 원칙

1. 학생들에게 공유할 SSH 정보는 반드시 `SSH over exposed TCP` 기준으로 준비합니다.
2. RunPod 연결 화면에 보이는 첫 번째 `Basic SSH` 명령은 VS Code Remote-SSH용이 아닙니다.
3. 수업 시작 후 Pod를 재시작하면 공인 IP 또는 외부 포트가 바뀔 수 있으므로, 수업 중에는 Pod를 불필요하게 재시작하지 않습니다.
4. `16개 Pod = 학생용 15개 + 강사용/예비용 1개` 구성을 권장합니다.
5. 인증 방식은 공개키(SSH key) 기반을 기본으로 사용합니다.

1. VS Code 설치
2. Windows 11에서 SSH 키 생성 후 공개키 제출

학생이 보내야 하는 것은 `.pub` 파일 내용만입니다. 개인키는 절대 제출받지 않습니다.

1. RunPod 공식 템플릿을 우선 사용합니다.
2. 가능하면 `RunPod PyTorch` 계열처럼 `SSH Terminal Access`를 지원하는 템플릿을 고릅니다.
3. 테스트 Pod 1개를 먼저 띄워서, 학교와 비슷한 Windows 11 환경에서 VS Code Remote-SSH 접속까지 검증합니다.

3. 각 Pod의 공인 IP와 외부 SSH 포트를 표로 정리합니다.

## 5. 인증 방식 결정

### 기본 권장안: 공개키 방식

가장 안정적이고 VS Code Remote-SSH와도 잘 맞습니다.

운영 방법은 두 가지가 있습니다.

### 방법 A: 강사 계정 설정에 학생 공개키 전체 등록

가장 간단한 운영 방식입니다.

1. 학생 15명 공개키와 강사용 공개키를 강사 RunPod 계정의 `SSH Public Keys`에 모두 등록합니다.
2. 그 상태에서 Pod를 시작하면, 시작 시점에 공개키가 Pod의 `authorized_keys`에 주입됩니다.

장점:

- 준비가 가장 빠릅니다.
- Pod를 16개 일괄로 띄우기 쉽습니다.

주의:

- 모든 Pod에 모든 공개키가 들어갈 수 있으므로, 접속 정보 배포를 엄격히 관리해야 합니다.
- 학생이 다른 학생 Pod의 IP/포트를 알게 되면 접속 가능성이 생깁니다.

### 방법 B: Pod별로 해당 학생 공개키만 넣기

보안상 더 바람직합니다.

1. Pod별로 `SSH_PUBLIC_KEY` 환경 변수를 사용하거나
2. Pod 시작 후 웹 터미널에서 `~/.ssh/authorized_keys`에 해당 학생 공개키만 추가합니다.

장점:

- 학생별 Pod 접근을 분리할 수 있습니다.

주의:

- 16개를 수작업으로 준비할 때 시간이 더 듭니다.

수업 운영 편의성을 우선하면 방법 A, 접근 통제를 우선하면 방법 B를 선택하면 됩니다.

## 6. RunPod 템플릿 준비

### 공식 템플릿을 쓰는 경우

1. Pod 생성 화면에서 공식 템플릿을 선택합니다.
2. `SSH Terminal Access` 또는 이에 준하는 SSH 노출 옵션이 있는지 확인합니다.
3. 가능하면 `/workspace`를 사용할 수 있도록 영구 스토리지를 함께 구성합니다.

### 커스텀 템플릿을 쓰는 경우

아래 조건을 모두 만족해야 합니다.

1. Pod 내부에 `openssh-server`가 설치되어 있어야 합니다.
2. `sshd`가 실행 중이어야 합니다.
3. 내부 TCP 22번이 외부에 노출되어야 합니다.
4. 학생 공개키가 `~/.ssh/authorized_keys`에 들어 있어야 합니다.

공식 템플릿이 아니라면, 수업 전날 반드시 VS Code 접속 테스트까지 끝내는 것을 권장합니다.

## 7. Pod 16개 생성 절차

1. Pod 이름 규칙을 정합니다.

예시:

- `class-pod-01`
- `class-pod-02`
- `class-pod-03`
- `class-pod-16`

2. 학생 실습에 필요한 GPU, 디스크, 템플릿을 선택합니다.
3. 가능한 경우 동일한 템플릿과 동일한 스펙으로 16개를 맞춥니다.
4. 학생용 15개와 강사용 1개를 모두 배포합니다.
5. 각 Pod가 완전히 올라올 때까지 기다립니다.

## 8. 학생에게 배포할 접속 정보 정리

각 Pod에서 아래 경로로 정보를 확인합니다.

1. RunPod 콘솔의 Pods 페이지로 이동
2. 대상 Pod 선택
3. `Connect` 클릭
4. `SSH` 탭 확인
5. `SSH over exposed TCP` 항목의 명령 확인

예시는 아래와 같습니다.

```bash
ssh root@213.173.108.12 -p 17445 -i ~/.ssh/id_ed25519
```

학생에게 전달해야 하는 핵심 정보는 아래 네 가지입니다.

- 호스트 IP: `213.173.108.12`
- 포트: `17445`
- 사용자명: `root`
- 원격 작업 폴더: `/workspace`

강사가 학생에게 명령 전체를 그대로 복사해서 줄 수도 있지만, 학생마다 Windows 사용자명이 다르므로 `-i` 경로까지 강사가 고정해서 전달할 필요는 없습니다.

가장 실용적인 전달 형식은 아래 둘 중 하나입니다.

### 전달 형식 A: IP/포트만 전달

- HostName: `213.173.108.12`
- Port: `17445`
- User: `root`
- Folder: `/workspace`

### 전달 형식 B: VS Code용 SSH config 예시 전달

```ssh-config
Host rp-class-01
    HostName 213.173.108.12
    User root
    Port 17445
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 60
```

## 9. 학교 네트워크 사전 검증

이 단계가 가장 중요합니다.

22번이 막혀 있어도 외부 고포트가 열려 있으면 접속할 수 있습니다. 따라서 수업 전에 반드시 학교 네트워크에서 실제 외부 포트로 연결 시험을 해봐야 합니다.

Windows PowerShell에서 예시는 아래와 같습니다.

```powershell
Test-NetConnection 213.173.108.12 -Port 17445
```

`TcpTestSucceeded : True`가 나오면 네트워크 레벨은 통과입니다.

만약 `False`가 나오면 다음 중 하나입니다.

1. Pod가 아직 준비되지 않음
2. 외부 포트가 바뀌었음
3. 학교 방화벽이 22번뿐 아니라 임의의 고포트도 차단함

세 번째 상황이면 VS Code Remote-SSH 방식은 그 네트워크에서 동작하지 않습니다. 이 경우 대안은 아래 중 하나입니다.

1. 학생 PC를 다른 네트워크에 연결
2. 모바일 핫스팟 사용
3. RunPod의 HTTPS 기반 접속 방식 사용
4. 브라우저 기반 도구(JupyterLab, 웹 IDE)를 수업 대안으로 준비

## 11. 수업 당일 운영 순서

1. 학생에게 각자 배정된 Pod 번호와 접속 정보만 배포합니다.
2. 학생들이 동시에 접속하기 전에 강사용 Pod로 먼저 접속 시연을 합니다.
3. 학생들이 접속 중일 때는 Pod 재시작을 하지 않습니다.
4. 접속이 안 되는 학생이 나오면 먼저 예비 Pod로 교체할지 판단합니다.
5. 한 학생의 Pod 문제를 오래 잡기보다, 예비 Pod로 우회하는 편이 수업 흐름을 지키기 좋습니다.

## 12. 자주 발생하는 문제와 대응

### 문제 1. RunPod에 SSH 명령이 하나만 보인다

원인:

- 템플릿이 `SSH over exposed TCP`를 지원하지 않을 수 있습니다.

조치:

1. 공식 템플릿인지 확인합니다.
2. `SSH Terminal Access`가 활성화된 템플릿인지 확인합니다.
3. 커스텀 템플릿이면 TCP 22 노출과 `sshd` 실행 여부를 확인합니다.

### 문제 2. 학생이 `Permission denied (publickey)`를 본다

원인:

- 공개키가 RunPod 계정 또는 Pod에 반영되지 않음
- 학생 PC의 개인키 경로가 다름
- Pod를 띄운 뒤에 공개키를 등록해서 자동 주입이 안 됨

조치:

1. 학생 공개키가 정확히 등록되었는지 확인합니다.
2. 공개키는 `ssh-ed25519 ...` 형식 전체가 들어가야 합니다.
3. Pod 시작 이후에 키를 넣었다면 웹 터미널로 `authorized_keys`를 직접 수정하거나 Pod를 다시 배포합니다.

### 문제 3. 학생이 갑자기 호스트 키 경고를 본다

원인:

- Pod 재시작 또는 재배포로 공인 IP 또는 호스트 키가 바뀜

조치:

학생 PC에서 아래 명령으로 기존 기록을 제거하게 안내합니다.

```powershell
ssh-keygen -R [213.173.108.12]:17445
```

그 뒤 다시 접속합니다.

### 문제 4. VS Code가 연결 중 멈춘다

원인:

- 네트워크 차단
- Pod 초기화 미완료
- VS Code Server 설치 실패

조치:

1. 먼저 `Test-NetConnection`으로 포트 도달 여부를 확인합니다.
2. Pod의 Telemetry가 들어오는지 확인합니다.
3. 이미 접속했던 Pod라면 원격에서 `~/.vscode-server`를 삭제한 뒤 재접속합니다.

```bash
rm -rf ~/.vscode-server
```

### 문제 5. 학생이 실수로 Pod를 중지했다

원인:

- RunPod가 외부 SSH 포트를 다시 배정할 수 있음

조치:

1. RunPod 콘솔에서 새 공인 IP와 새 외부 포트를 다시 확인합니다.
2. 학생 SSH 설정을 다시 업데이트합니다.
3. 시간이 부족하면 예비 Pod로 전환합니다.

## 14. 차선책: 비밀번호 방식

공개키 수집이 현실적으로 어렵다면, RunPod의 비밀번호 기반 SSH를 차선책으로 쓸 수 있습니다. 다만 수업 운영에서는 아래 이유로 기본안으로 권장하지 않습니다.

1. Pod별 비밀번호를 따로 관리해야 합니다.
2. 학생이 재접속할 때마다 비밀번호를 입력해야 할 수 있습니다.
3. 수업 중 비밀번호 전달과 재설정 관리가 번거롭습니다.

따라서 시간이 허락하면 공개키 기반으로 준비하는 것이 더 낫습니다.
